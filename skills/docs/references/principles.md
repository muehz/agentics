# Documentation principles: load when you author or maintain documentation

Apply in every mode:

1. **Clarity.** Use simple, clear, unambiguous language.
2. **Accuracy.** Keep all code snippets and technical details correct and current.
3. **User focus.** Help a specific reader complete a specific task.
4. **Consistency.** Keep tone, terminology, and style consistent across the document.
5. **Repository awareness.** Before you draft, read existing files for tone, style, and terminology, and match them. Do
   not copy their content unless the user asks for it.
6. **Targeted edits.** Use `str_replace` or targeted patches. Never reprint the whole document.
7. **Diátaxis lens.** Map every doc to one of the four types. The skill body's table is the authority.
   [technical-writing.md](technical-writing.md) Layer 1 explains how to write inside each type.
8. **Code over docs.** Update the documentation to match the implementation. Never change the implementation to match
   the documentation.
