# Surface docs

Coding tools don't agree on what a plugin can contain or how its parts load. The documents in this directory record each
tool's published requirements, how Agentics packages for them, and what has been observed in a live test.

Start with the [verified package setup](../guide/01-setup.md) before registering Agentics with a coding tool.

This README is also the review ledger. The table is intentionally specific because the scheduled reminder and
conformance suite read it. A date here means the linked requirements were reviewed. It doesn't mean every behavior was
tested again.

### Stamp conventions

Two kinds of freshness records, deliberately distinct:

- **Behavioral probe records** live inline in the surface docs. Current verified claims may use
  `Verified on <CLI> <version> (YYYY-MM-DD)`; superseded or version-specific evidence is explicitly labeled historical
  or retained. Each record means a specific claim was exercised against that host and version. Add one whenever a probe
  runs; never refresh a probe date without re-running it.
- **Requirements reviews** live only in the ledger above. A review means the provider's published plugin/marketplace
  docs (the pinned sources) were re-read and diffed against Agentics's packaging claims. A review is not a probe, and
  neither stamp substitutes for the other.

### Review cadence

- Review each surface every **30 days** and immediately after a local CLI upgrade or any install/validate failure that
  contradicts a surface doc.
- The scheduled `Reminders` workflow's ledger staleness job opens or updates a tracking issue when any row exceeds the
  budget. It runs the conformance suite's `docs` domain with `AGX_LEDGER_MAX_AGE_DAYS=30`; PR CI invokes conformance
  without that age-check variable. The scheduled step uses `continue-on-error`, and a failed staleness outcome drives
  the issue update rather than failing PR CI.
- A row whose Result opens with `Retired:` is exempt from the age budget, so its date stays as the last review.

### Review playbook (per surface)

1. **Fetch** the pinned sources, plus the provider's release notes since the row's `Last reviewed` date. Follow into the
   plugin-adjacent subpages (manifest schema, hooks, skills discovery). Marketplace requirements rarely change alone.
2. **Diff** the published requirements against Agentics's claims in the applicable surface doc, `docs/ARCHITECTURE.md`,
   `hooks/README.md`, and the surface's manifest and hook config files listed in that surface doc's Configuration
   section.
3. **Probe** locally where behavior matters, using the validation and **Live check** steps in the surface doc; update or
   add inline `Verified on` stamps for what was actually exercised.
4. **Fix** drift through normal PRs; a user-facing change is described in the PR's `## What changed` section, which
   becomes the commit body on squash. A retired surface also gets a row in [`../RENAMES.md`](../RENAMES.md).
5. **Update the row.** Record the current source-review date separately from the exact retained probe version and date,
   then add a one-line result. Use `No drift` or the open follow-up the next review inherits. Never advance a behavioral
   probe record when only the published docs were re-read.
